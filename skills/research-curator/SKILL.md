# 큰 자료조사 (수집형 · 분석형)

결과가 «항목 표»(카드·행)로 쌓이고 사람이 그중에서 고르거나 판정하는 조사를 끝까지 진행하는 방법이다. 여러 번의 실제 조사(영상 기준집 2건 · 디자인 레퍼런스 보드 · 공개 가격 데이터 분석)에서 실패한 지점을 고친 순서다. 주제는 바꿔 끼운다.

**왜 따로 스킬이 있나:** 큰 조사는 «많이 찾는 것»보다 «찾은 것이 진짜인가 · 중복은 없나 · 사람이 빨리 고를 수 있나»에서 무너진다. 실제로 있었던 일: 주소 문자열로 중복을 거르다 서로 다른 영상 34건이 빠졌다 · 하위 조사자가 «열어 봤다»고 한 링크 일부가 없는 페이지였다 · 요약 상자 숫자(105편)와 데이터(207건)와 실제 확인(86편)이 서로 달랐다 · 콘솔 출력 뒤에 저장하다 인코딩 오류로 14회분이 날아갔다. 아래 절차와 `scripts/` 코드는 이것들을 막는다.

## 0. 쓸 때 / 안 쓸 때
- **쓴다:** A **수집형**(레퍼런스 보드·사례집·업체 목록·게시물 모음 → 카드 N건 + 고르는 화면) · B **분석형**(공개 데이터 수집·매칭·계산 → 계산 표 + 신뢰 한계).
- **안 쓴다:** 질문 하나에 서술형 보고서 한 편 · 한두 개 사실 확인 · 특정 기업 하나의 심층 분석.
- 서술형 보고서가 따로 필요하면 이 절차로 표를 만든 뒤 마지막에 보고서를 쓴다.

## 1. 재사용 먼저 (비용 0)
같은 주제의 앞선 조사가 있으면 이어서 한다 — 카드 데이터 JSON · `seen_ids.txt` · 질문지 · 2차 조사 지시문을 그대로 다시 쓴다. 이미 모은 것을 다시 모으는 데 드는 비용이 가장 아깝다.

## 2. 조사 한 장 (시작 전에 확정 · 결과 파일 머리에 그대로 붙임)
| 칸 | 적을 것 |
|---|---|
| 목적 | **이 결과로 무엇을 결정하나** · 누가 · 결정 방식(예: «좋음 3 · 싫음 2 번호 고르기» / «채택·보류·기각») |
| 유형 | A 수집형 / B 분석형 |
| 기준선 | 무엇이 «좋은 것»인가 — 벤치마크 대상. (실제 실패: 기준선을 잘못 잡아 레퍼런스 수집이 세 번 빗나갔다) |
| 범위 묶음 | 서로 겹치지 않는 하위 범위 · 제외 목록(이미 가진 것) |
| 필드 | 항목 하나 = 한 줄. 1차·2차 조사자 모두 같은 필드 이름·순서 |
| 상태값 | `opened`(실제로 열어 봄) / `unverified`(못 엶·확정 못 함) / `dead`(없음) · 분석형은 매칭 등급(A 확정 / B / C 후보 / X 제외) |
| 근거 강도 | **강** = 1차 출처(본인 글·공식 자료·원자료)에 근거 문장이 그대로 있음 · **중** = 2차 출처(기사·모음 페이지) · **약** = 근거 원문 없음·추정. 줄마다 `basis: 근거/가정` |
| 점수 | 1~5 기준을 글로. «추정 점수»(글만 봄)와 «실측 판정»(직접 보거나 계산)을 다른 칸에 |
| 완료 기준 | 수량 · 실측 비율 · 공개 전 검토 횟수 |

수집형 기본 필드: `no · title · url · id(정규화) · platform · account · desc · evidence(근거 원문 짧게) · metrics(수치+확인일) · why_good · our_use · status · score · measured_score · source · checked_at`.
분석형 기본 필드: `원자료 출처·조회일 · 키 · 매칭 등급 · 비교 집단 정의 · 값 · 값 성격(관측/근사/기사 제시/계산)`.

## 3. 비용 견적 → 사용자 확인 (돈·큰 사용량은 확인 뒤)
시작 전에 표로 보이고 **더 싼 방법 1~2개**를 같이 적는다. 유료 API 는 상한을 먼저 정하고 넘으면 멈춘다(`scripts/ledger.py`).
| 항목 | 기준(실측 예) | 이번 예상 |
|---|---|---|
| 하위 조사 에이전트 1개 | 약 15~20만 토큰 | 개수 × |
| 영상 이해 모델 API 시청 | 편당 약 US$0.05~0.07(길이 비례) | 편수 × · 상한 |
| 영상 플랫폼 검색 API | 할당량 단위 | 횟수 |
| 화면 캡처 | 사이트당 PC 1 + 모바일 1~2 | 곳 수 |
| 2차 독립 조사 | 다른 AI 구독·동료(추가 비용 대개 0) | 회 |
| 외부 검토 | 안건당 최대 2회 | 회 |

- 에이전트당 도구 호출 상한: 쉬움 5회 미만 · 보통 5~10 · 어려움 10~15 · 절대 20. 넘으면 저장한 것으로 끝내고 «남은 범위»를 보고한다.
- 에이전트 수는 0~2개가 기본. 넓이형(서로 다른 대상 여럿)만 묶음당 1개 · 실측 상한 4개 — 10개로 늘려도 결과는 비례해 늘지 않았다(병목은 «원문 접근»).

## 4. 접근 표본시험 (본 조사 전 · 경로마다 3~5개)
경로마다 표본을 실제로 열어 «열림 / 막힘 / 부분»을 표로 남긴 뒤 도구를 정한다. 막힌 경로는 범위에서 지우지 말고 «미확인 묶음»으로 둔다.
| 경로 | 흔한 상태 |
|---|---|
| 일반 웹·기사 | 웹 검색·가져오기로 대체로 열림 |
| X·틱톡 | 로그인된 브라우저에서 읽기만(좋아요·팔로우·댓글 0). 화면 글자 읽기 우선 |
| 인스타그램 | 로그인 없이는 거의 막힘 |
| 유튜브 내용 | 영상 이해 모델 API 에 공개 URL · 후보 찾기는 검색 API |
| 로그인·약관상 자동 접근이 막힌 사이트 | 우회하지 않는다 → 사람이나 허용된 도구가 보는 «인수 메모»로 넘긴다 |
| 공개 통계 | 공식 API·다운로드 → 원자료 파일 그대로 보관 |

## 5. 조사 실행
**5-1. 하위 조사 에이전트** — 범위만 바꾼 **같은 틀**(조사 한 장 + 필드 + 상태 규칙)을 준다. 공통 규칙: 호출 상한 · 실제로 연 것만 `opened` · 근거 필수 · 링크·숫자 지어내기 금지 · 수치는 확인 날짜와 함께 · `seen_ids.txt` 의 ID 는 건너뜀 · 결과는 `research/<묶음>.json` · 끝 보고 250~350단어.

**5-2. 2차 독립 조사** — 다른 AI(다른 회사 모델이면 더 좋다)나 동료에게 같은 목적·필드·상태 규칙으로 붙여넣기용 지시문을 만들어 준다: 역할 · 배경 · 묶음 · 포함/제외 조건 · **이미 가진 것 목록** · 규모 · 출력 형식(마크다운 표 한 개 · 열 이름 고정 · 칸 안 `|` 금지) · «요약 5줄 / 못 찾은 곳» · «수치 추정 금지 · 링크 지어내기 금지 · 직접 열어 봄 예/아니오». 출력의 `source` 는 `gpt`·`person` 처럼 1차와 다른 값으로.
- 1차 결과를 2차 조사자에게 먼저 보여 주지 않는다(제외 목록만 공유). 먼저 본 조사는 «독립»이라 부르지 않는다.
- 실측: 두 번 모두 **겹친 링크 0건**이었다 — 겹침으로 신뢰를 올리기보다 «서로 보완»으로 합친다.
- 선택: 양쪽 원문이 저장된 뒤 1차 표를 2차 조사자에게 주고 «누락·반론·근거 부족»을 받는다.

**5-3. 실측 판정(있으면)** — 영상이면 편마다 같은 질문지 + 끝에 JSON. 상한·장부·긴 영상 건너뛰기 기준을 스크립트 머리에.

**5-4. 저장 규칙** — 검색·호출 **1회마다** 바로 파일로(`scripts/rounds.py` 의 `save_round`). 콘솔 출력 뒤에 저장하면 인코딩 오류 하나로 그동안의 결과가 날아간다. 회차마다 따로 저장하고 덮어쓰지 않는다. 원자료는 고치지 않고 정정은 별도 폴더에.

## 6. 합치기 · 검증
**6-1. 중복은 고유 ID 로** — 주소 문자열로 비교하지 않는다. `scripts/norm_id.py` 의 `norm_id(url)` 를 쓴다.
- 플랫폼(유튜브·X·틱톡·인스타·스레드): 호스트 정확 일치 + 경로 세그먼트 전체가 ID 일 때만 ID.
- 일반 웹: 경로 대소문자·쿼리 순서 보존, 추적 키(`utm_*`·`fbclid`·`gclid`·`igsh`·`igshid`)만 지움.
- **애매하면 합치지 않는다** — 잘못 합치면 자료가 조용히 사라지지만, 중복이 남으면 사람이 표본으로 보면 된다. ID 를 못 뽑은 항목은 `id=None`(+사유)으로 남긴다.

**6-2. 링크 실재 · 근거 원문 확인(코드 · 공개 전 필수)** — 하위 에이전트·2차 조사자의 «열어 봄»을 믿지 않고 `scripts/link_check.py` 가 다시 연다.
- 상태와 사유를 남긴다: 404·410·도메인 없음 = `dead` · 403·로그인·robots 금지·따라가지 못한 리다이렉트·동의/차단 화면·소프트 404 의심 = `unverified`. 애매하면 `opened` 로 확정하지 않는다.
- `evidence` 문장이 페이지 글자에 실제로 있는지 대조(`found/not_found/not_checked/empty`) — 없으면 근거 강도를 «약»으로 내린다. 유튜브는 제목·채널(메타데이터)만 대조된다는 점을 화면에 표시.
- 계정·제목이 다르면 `conflict` 로 모은다(지우지 않는다).
- 요약 한 줄: «링크 N 중 열림 a · 막힘 b · 없음 c · 근거 원문 확인 d».

**6-3. 숫자는 데이터에서 코드로** — 요약 상자·건수·평균은 카드 JSON 에서 스크립트로 다시 만든다(`scripts/cards_html.py`). 데이터를 바꾸면 화면도 다시 만든다. 반올림 규칙을 적는다.
**6-4. 점수 우선순위** — 실측 > 추정. 화면에서 둘을 구분하고, 다르면 실측으로 덮고 차이를 기록.
**6-5. 분석형 추가** — 계산은 순수 함수 + 시험 · 비교 집단 정의를 문장으로 · 매칭 등급별 집계 · «관측/근사/기사 제시값/계산값» 구분 · 신뢰 한계(표본 쏠림·대표성·정의 미확정·소수 표본·특이값)를 결론과 같은 무게로. 결론마다 `근거/가정`. 실제로 계산 정의 하나를 빠뜨려 핵심 비교 수치가 크게 바뀐 적이 있다 — 계산 정의는 검토 전에 한 번 더 스스로 대조.
**6-6. 외부 검토** — 업무 판단에 쓸 결과는 다른 모델 계열이나 사람이 안건당 최대 2회 반박 검토. 답 머리에 실제 검토자를 적는다. 고르는 화면(비공개)은 먼저 보여 주고 검토와 병행해도 된다.

## 7. 결과물
- **수집형:** 카드형 고르는 화면 — `scripts/cards_html.py`(거르기 칩[점수 4 이상 · 열어 본 것만 · 근거 강 · 실측한 것 · 2차 조사분] · «마음에 듦/안 듦» · 고른 번호 복사 바 · 요약 상자). 첫 줄에 고르는 법(예: `좋음 1 3 17 · 싫음 18 21`). 공유가 필요하면 그 HTML 을 그대로 아티팩트·웹 페이지로 올린다.
- **분석형:** 계산 표 + 대시보드 + 신뢰 한계.
- **재사용 꾸러미 폴더:** `README_재사용안내.md`(조사 한 장 · 방법 · 실측 비용 · 막힌 곳 · 실수 · 2차 조사 지시문 원문 · 점수 정의 · 고른 번호) · `카드데이터.json` · 화면 HTML · `research/*.json`(회차별) · `seen_ids.txt` · `link_check.json` · 비용장부 · 스크립트.
- 결과 요약은 4칸: 무엇을 쓸 수 있나 / 무엇이 안 되나 / 되돌리는 법 / 지금 결정할 것.

## 8. 끝 — 결정으로 닫기
사용자가 고른 번호·판정을 README 에 적고, 다음 단계가 있으면 이어 붙인다. «쓸 만한 게 없다»도 결과다 — 이유 한 줄 + 폴더 색인으로 보관한다. 조사 한 장의 «결정 방식»이 틀렸으면 다음 조사를 위해 적는다. 실제 든 비용(에이전트 수 · 유료 호출 · 사람 시간)을 기록하면 다음 견적의 단가가 된다.
